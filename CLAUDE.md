# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

NanoThumbnail is a free, open-source, local-first studio to generate, edit and test YouTube thumbnails with Google's Nano Banana models (Pro / 2), BYOK via Replicate, Google Gemini, OpenRouter or Mammouth, or Vertex AI through the user's gcloud (local only).

**Stack**: Astro 7 (static), React 19 island for `/app`, shadcn/ui + Radix + Tailwind v4, Zustand, IndexedDB (`idb`), Vitest. Deployed on Netlify.

## Commands

```bash
npm run dev        # http://localhost:4321 (Gemini/OpenRouter work; Replicate needs `netlify dev` for the proxy)
npm run build      # → dist/
npm test           # Vitest
npm run typecheck  # tsc --noEmit (src + netlify)
npm run check      # typecheck + test + build (CI)
npm run local      # build + local server (dist + Vertex helper + Netlify functions) on 127.0.0.1:17830
npm run app:mac:install  # macOS app → /Applications (macos/auto-install.sh does it when sources changed)
```

## Architecture

- `src/app/` — the studio, a single React island (`<App client:only="react" />` in `src/pages/app.astro`).
  - `stores/workspace.ts` — core state & actions: projects, generations (with `parentId` lineage), jobs (abortable), brief (title, scene, style), refs, personas, brand (channel name, logo, colours), edit/region-edit, rank.
  - `stores/settings.ts` — provider, keys (localStorage or sessionStorage), output params, theme, lang, the edit bar's position. Keys: `nt_prefs`, `nt_key_<provider>`, `nano_lang`.
  - `lib/providers.ts` — Replicate (via proxy, `Prefer: wait`, backoff polling, cancel on abort) Gemini (direct, `x-goog-api-key`), OpenRouter and Mammouth (direct, same OpenAI-style chat completions code, per-provider endpoint/models in `CHAT_PROVIDERS`) and Vertex AI (same body as Gemini, sent to the same-origin `/vertex/*` helper; the key is optional, `apiKey()` returns the `VERTEX_GCLOUD` sentinel when empty). `generateImage`, `generateText`, `generateJSON`.
  - `lib/prompt.ts` — prompt builder following Google's Nano Banana guidance (declared image roles, identity lock, "change only X" edits). Covered by tests. Every prompt sent to the models (here, in `lib/styles.ts` and `lib/ai.ts`) is written in French, whatever the interface language; only the edit suggestions follow it (`iterate.quickEdits`).
  - `lib/ai.ts` — ranking and concepts (Gemini 3 Flash).
  - `lib/images.ts` — canvas helpers: reference downscaling, YouTube export (1280×720 or 1920×1080, ≤ 2 MB; images smaller than 1920×1080 are first upscaled by the model — `upscale` in the workspace store, a `kind: 'upscale'` version), mask highlight/merge for region edits.
  - `lib/db.ts` — IndexedDB `NanoThumbnail` (stores Blobs; WebKit now and then refuses one, cause unknown, so `lib/blobStore.ts` retries a generation once with an in-memory copy). `lib/migrate.ts` imports v1 data (`NanoThumbnailDB`) once. `lib/reset.ts` (Settings, « Réinitialiser l’application »): deletes both databases and the app's `localStorage`/`sessionStorage` keys, then reloads.
  - `lib/styles.ts` — 14 style presets, each with an emoji; `allStyles`/`findStyle` also cover the user's own styles.
  - `lib/colors.ts` — brand colour hex parsing and the 10 preset palettes. `lib/fonts.ts` — Google Fonts for text blocks: curated list shipped in `public/fonts` (latin subset, regular + heaviest weight, fetched by `npm run fonts:download` / `scripts/download-fonts.ts`; add a family to `GOOGLE_FONTS` then rerun it), loaded with the FontFace API; other families typed by the user go through the Google Fonts CSS API (its 400s have no CORS header, so a failed fetch while online means "not available").
  - Channel preview (`components/canvas/ChannelPreview.tsx`, view `channel`, ported from NanoChannel): a YouTube channel page (Videos tab) drawn on a canvas by `lib/channelRender.ts` (geometry in `channelLayout.ts`, helpers and seeded stats in `channel.ts`, Roboto from `@fontsource/roboto`, icons from `lucide`), live and exported at 2560×1440. Channel details come from the brand kit (name, logo, banner, handle, counts, description, verified); the six videos are per project (`Project.channelPage`: placed versions and titles, theme, seed), empty slots filled by `fillSlots` with the selected thumbnail then the project's others.
  - Thumbnails and versions (`lib/versions.ts`): a thumbnail is an original image (generation or import) plus every version derived from it through `parentId`. The project strip (`Filmstrip.tsx`, headed by the project name and its thumbnail / favourite counts) shows one tile per thumbnail (video title above, the selected version else the latest, version count; tiles are sized in pixels, as WebKit ignored percentage height + aspect-ratio; export picks are per thumbnail); right-clicking a tile or the image view (`components/ImageMenu.tsx`, not while a tool is active) offers an independent copy of that version (`duplicateSelected`); the versions panel (always shown, the original alone when nothing was edited) shows the whole tree of the selected one (`versionTree`, linked by dashed lines from `treeLines`), each step named by `Generation.action` (reframe, smooth, heal) or its `kind`. Every new image, version or original, is saved by `saveVersion` in the workspace store: `newGeneration` (pure, tested) inherits the parent's project, video title and params, and it is shown (`select`, one rule for every tool) only if its project is still open, the one a job started in. In-place changes (favourite) go through `replaceVersion`.
  - History panel (`components/iterate/IteratePanel.tsx`, « Historique »): the versions. The edit bar (`components/canvas/EditBar.tsx`) floats under the image on desktop (`CanvasArea` keeps room for it, more for the text and area tools: a long instruction, growing upward, or a toolbar wrapping in a narrow window can still reach the image) and sits below it on mobile, in the image view: the free instruction (held by `CanvasArea`, so it survives other views and tools, not a reload), the image tools (`COMMANDS`, named by `shortLabel`, icons alone when it is narrow), the suggestions menu (a click replaces the instruction with its text, nothing is sent), the prompt eye and send. The text, arrow and reframe toolbars take the whole bar (`EditBarShell`). On desktop its handle moves it (`lib/editBar.ts` keeps it inside the area, tested; `editBarOffset` in the prefs, per device). The view switcher sits in the top bar (above the canvas on mobile); the image actions (favourite, export, « … » menu with safe zones) float over the top-right of the image view.
  - Image tools: one at a time in `tool` (`'mask' | 'text' | 'arrow' | 'reframe' | null`) of the workspace store, changed only by `setTool`, which runs each tool's entry and exit (text and arrow drop the draft on leaving, and start with a block of their kind when it has none; switching between them keeps the draft; reframe resets the framing, the painted area goes with the mask tool); `select` and new versions leave the tool. The active tool's controls are in the edit bar: the text and reframe toolbars take all of it, the area ones (`maskControls`) replace its tools, under the instruction.
  - Text tool (`T`): `components/canvas/TextLayer.tsx` (overlay to move/rotate blocks + style toolbar, with `FontPicker`), blocks in `stores/text.ts`, layout and canvas render in `lib/textBlocks.ts`, drawing blocks into an image and naming the result in `lib/textLayer.ts` (`renderText`, `textSteps`, `textSummary`); positions and sizes are relative to the image, with shared metrics so the overlay matches the render. A new text block is white on a black box in Bricolage Grotesque (`newTextBlock`, `DEFAULT_TEXT_FONT`); the box's corners are square, rounded or pill (`corners`, `boxRadius`; absent = rounded). The tool also places curved arrows (`ArrowBlock`, `kind: 'arrow'`; text blocks have no `kind` or `'text'`), edited with their own tool (`A`): each tool only reaches its own kind of block, the other kind stays faded on screen. An arrow is a quadratic curve whose `arrowGeometry` gives SVG path data used by both the overlay and the canvas (`Path2D`), with head type, thickness, bend, colour, border, dashes and drop shadow with its strength (`shadowOpacity`; new arrows: no border, a light shadow). `applyText` draws them into the image for good: one new `kind: 'text'` version for the texts and one for the arrows (`action: 'arrow'`). Nothing stays editable: a mistake means going back to the previous version. (Versions made before this may still hold an old `textLayer` in IndexedDB; it is ignored, their `blob` already shows the text.)
  - Reframe tool (`R`): `components/canvas/ReframeLayer.tsx`, framing in `stores/reframe.ts`, math and composition in `lib/reframe.ts` (scale + centre offset relative to a frame of the image's own size). `reframe` builds the result locally when the image still covers the frame; otherwise the empty areas are painted `GAP_COLOR`, filled by the model (`buildOutpaintPrompt`) and merged back with `mergeWithMask` so the moved image stays pixel-exact. « Zone » mode moves only a freehand lasso zone (`composeZoneReframe`): its old place is painted `GAP_COLOR`, and so is a band (`SEAM_BAND`) along the moved zone's cut edges (`seamEdges`, not the ones lying on a frame side): shown a hard edge, the model copied it instead of blending it. Reframe merges use `mergeWithMask(…, solid)`: a mask blurred both ways faded at the canvas sides and let the grey show.
  - Trackpad pinch: `hooks/use-pinch.ts` (ctrl+wheel in Chromium, `gesture*` events in WebKit/the macOS app). The image view zooms 0.15–8× (`lib/zoom.ts`): around the cursor above fit, centred below it (to see the thumbnail small), with a stop at fit, the reframe view scales the image.
  - Area tool extras: « Lisser » (`smooth`, `lib/smooth.ts`): the painted area is refilled locally from its surroundings (pull-push interpolation + Laplace relaxation), no AI. « Correcteur IA » (`heal`): the same local fill first, then a region edit with `buildHealPrompt` that only restores texture, always on Nano Banana 2 whatever the chosen model (the area tool shows a tip under the image: paint well around the area, for context); sent as a highlighted or grey hole, Nano Banana drew an object of the area's shape. Region edits share `regionEdit`.
  - Image calls: every Nano Banana call goes through `runJob` in the workspace store (generate, edits, region edits, heal, reframe, upscale), except the concept previews the assistant can generate when its box is ticked (`previewConcept`, Nano Banana 2 Lite, from the concept's text alone with no attached image, saved only by « Ajouter au projet », `addConceptImage`). The assistant only takes the video title, shared with the brief. While any job runs, `BlockingJobOverlay` (`components/canvas/BlockingJob.tsx`) locks the studio (clicks and shortcuts) with its label and one cancel button for all of them, and the central panel is blurred (`CanvasArea`); failed jobs stay as chips under the image until dismissed.
  - Edit prompt (`buildEditPrompt`): the instruction must win over the "keep everything else" clause, which only protects what the instruction does not mention (a fixed "keep the composition" made the model ignore moves and resizes).
  - Feed preview (`components/canvas/FeedPreview.tsx`): the selected image alone among 30 real YouTube videos shipped with the app (`src/app/data/feed-videos.json` + thumbnails/logos in `public/feed/`), drawn with a seeded shuffle per layout (« Mélanger » = new seed); ages are relative to the snapshot date. Your card uses `brand.channelName` and `brand.logo`. No key or call at runtime: refresh the snapshot with `npm run feed:update [REGION]` (`scripts/update-feed-videos.ts`, YouTube Data API v3 most popular videos, key from `YOUTUBE_API_KEY` or the gcloud key « NanoThumbnail YouTube… », never printed).
  - Per-project brief panel: `Project.inputs` holds everything in the left panel (brief, references, brand kit with channel/logo/banner/colours, the people selected for its thumbnails, output settings), saved 300 ms after a change (`scheduleSave`/`flushSave` in the workspace store; output settings live in the settings store, watched by a subscription) and restored by `openProject`. A new project starts empty (named first in `NewProjectDialog`); a project made before this gets a copy of the values that were shared (`nt_brief`, the `brand` store record, the first people, the output prefs). Only app settings (provider, keys, theme, language, the edit bar's position) and the people library are shared.
  - People: « Bibliothèque de personnes », the `personas` store, shared by every project and unlimited (`personas` in the workspace store, loaded by `init`). Each project selects at most `MAX_PERSONAS` (5) of them for its thumbnails (`personaIds`, saved as `inputs.people` whenever it changes, by a store subscription); a person just created joins the open project's selection while there is room.
  - Styles: « Bibliothèque de styles » (`components/dialogs/StyleDialog.tsx`, opened from the brief panel's style button and the command palette) chooses the project's style (`brief.styleId`) and creates, edits and deletes the user's own styles, each card showing whether the style puts text in the image (a preset's `preset.text`, `CustomStyle.addsText`): the `styles` store (`CustomStyle`, IndexedDB version 2), shared by every project and included in backups (`customStyles` in the workspace store, loaded by `init`). A project whose style was deleted falls back to none.
  - Brief panel (`components/brief/`, every block of the generation prompt shows on hover or tap of an eye beside its input's title, `PromptEye` through `Field`'s `prompt`, from the same functions as `buildGenerationPrompt`: `titleLine` (`titlePreviewLine` shows it with a placeholder while the title is empty, nothing is sent then), `sceneLine`, `styleLine`, `colorsLine`, `formatLine`, `textLine`, `titleZoneLine`, `qualityLine`, `marginLine`, `priorityLine`, `previewImageLines` in the store, and a test checks nothing else is sent; `AdvancedOptions`, `GeneratedTextField` (locked on when the style adds text) and `TitleZonePicker` hold `brief.options`, saved per project, over the style's `preset` (`resolveOptions`; choosing another style brings its preset back, `optionsForNewStyle`), and each reference has a role (`RefImage.use`); the style picker is a centred dialog showing each style's text; every input has its title above it, with `Field`; the numbered sections fold from their title, `Section`'s `foldable`, only the advanced options start folded and this is not saved): `ChannelSection` (channel name and logo, typed or fetched from a channel/video URL by `netlify/functions/youtube-channel.ts`, mounted in `local/server.ts` too, which also brings the channel banner for the channel preview (`bannerUrl`: the page data's `imageBannerViewModel`, largest source up to 2560 px); the logo is for the feed preview only; setting the name renames the current project when it still has its default name, `DEFAULT_PROJECT_NAMES`), brief (format, 16:9 or 9:16 only, `OutputRatio`: an older image keeps its other ratio for its edits, `outputRatio` brings a saved one back to 16:9 for new images; title, scene, style), people, references, `BrandColors` (sent in the prompt), output, advanced options (model with its price from `lib/pricing.ts`, Lite being 1K only, resolution, brand weight) with the blocks always added at their bottom: the order of the prompt, with the channel first, folded to one line once filled as it never reaches the model. There is no on-image text in the brief: the prompt asks for clean space, text and arrows come from the text tool.
  - `components/canvas/EditPromptEye.tsx` — the eye of the edit bar, on hover (`PromptEye`): the prompt, the images, the painted area and the model the next edit would send (`previewEdit`, built from the same helpers as `edit`).
  - `components/dialogs/PromptDialog.tsx` — the eye button next to Generate: the prompt the next generation would send (`previewPrompt()`, same code path as `generate`) and the `fullPrompt` stored on the selected generation.
  - `i18n/` — typed dictionaries; `useT()` in components, `t()` elsewhere. `fr.ts` must satisfy the `en.ts` shape.
  - `components/ui/` — shadcn components (generated; `cn` comes from `@/app/lib/utils`).
- `src/components/site/Landing.astro` + `src/site/i18n.ts` — static landing, pre-rendered in fr (`/`) and en (`/en/`), no client JS. Images live in `src/assets/` and go through `<Image>` (responsive srcset). The style gallery (`src/assets/gallery/`) holds one thumbnail per preset in `lib/styles.ts`, generated in the studio: `<id>.webp` (FR or language-neutral text) and `<id>-en.webp` when the text differs in English. Styles: `src/styles/site.css` (scans only the site, inlined) vs `tailwind.css` (studio); shared tokens in `tokens.css`.
- SEO/GEO: `SiteLayout.astro` (Open Graph per language `public/og-{fr,en}.jpg`, hreflang, JSON-LD WebApplication + FAQPage), `src/pages/sitemap.xml.ts`, `src/pages/llms.txt.ts` and `llms-full.txt.ts` (generated from `src/site/i18n.ts` via `src/site/llms.ts`), `public/robots.txt` (AI crawlers allowed). Landing currently scores 100/100/100/100 on Lighthouse (mobile and desktop).
- `src/app/agent/` + `mcp/` — AI agent bridge. `mcp/` (npm workspace `nanothumbnail-mcp`, bundled with esbuild) is a stdio MCP server that relays tool calls over a WebSocket on `127.0.0.1:17821` to the studio tab (`agent/bridge.ts`, paired with a token via `#agent=<port>:<token>`). Tool definitions are shared in `agent/protocol.ts` (pure, no DOM/Node); handlers in `agent/tools.ts` call the store actions (`generate`/`edit`/`rankPicked` return an `Outcome` for this). Adding a tool: define it in `STUDIO_TOOLS`, implement it in `handlers`. `skills/nanothumbnail/` is the companion agent skill (skills.sh format: `SKILL.md` + `references/`); keep it in sync with the tool list.
- `local/` — `vertex.ts`: connect-style middleware that relays `/vertex/models/{model}:generateContent` with a cached `gcloud auth print-access-token` and the gcloud project (local Host + same Origin only; tested). Mounted in `astro dev` by an integration in `astro.config.mjs` and by `server.ts`, the static server bundled (esbuild → `local/dist/server.mjs`) into the macOS app, which also adapts the Netlify functions. `macos/` — `NanoThumbnail.swift` (AppKit + WKWebView: starts the server with the login-shell `PATH`, handles downloads, file pickers, external links) and `build.sh` (swiftc, Info.plist, icon, ad-hoc signature). The port 17830 is fixed: IndexedDB is tied to the origin.
- `netlify/functions/replicate-proxy.ts` — relays only create/poll/cancel Replicate routes, only for the site origin (`netlify/lib/origin.ts`). Tested.
- `public/sw.js` — service worker (network-first pages, cache-first hashed assets). Bump `VERSION` when changing its logic.

## Conventions

- Adding UI text: add the key to both `src/app/i18n/en.ts` and `fr.ts` (typecheck enforces parity).
- New shadcn components: `npx shadcn@latest add <name>`; check the import of `cn` afterwards, and note that a stale `deno.lock` in the repo makes the CLI try to use Deno.
- CSP is emitted by Astro (`security.csp` in `astro.config.mjs`). Any new external origin (image CDN, API) must be added to `img-src`/`connect-src` there.
- Keyboard shortcuts (letters case-insensitive, ignored while typing or with a dialog open): ⌘↵ generate, ⌘K palette, P feed preview, C channel preview, Z safe zones, T text, A arrow, M paint an area, R reframe, Esc leaves the current tool. The letters are `COMMANDS` in `src/app/commands.ts`, which also fills the command palette and the edit bar's tools (label, icon, needs an image, pressed state); add a command there, and `commands.test.ts` checks one letter per command. ⌘↵, ⌘K, Esc and Delete stay in `App.tsx`.
- Don't put API keys in URLs; don't cache anything under `/.netlify/` in the service worker.
